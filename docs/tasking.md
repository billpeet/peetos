# Tasking and Scheduler

This document describes the tasking and scheduler implementation. It supports kernel threads and multiple user processes (`fork`/`vfork`/`clone` without threads, `execve`, `wait4`), with preemptive round-robin scheduling driven by the PIT.

**Where It Lives**
- `kernel/src/task.rs`
- `kernel/src/sched.rs`
- `kernel/src/user.rs`
- `crates/arch_x86_64/src/idt.rs` (interrupt hook for preemption)
- `crates/arch_x86_64/src/pit.rs` (tick hook)
- `kernel/src/main.rs`

**Task Structure**
`kernel/src/task.rs` defines the `Task` struct and task table. Each task stores:
- IDs (PID/PPID, plus `tgid` and `group_leader` for thread groups; see `docs/process_model.md`)
- Name
- State and flags
- Saved interrupt-frame stack pointer (`saved_rsp`)
- Kernel stack base/top
- User-process metadata (`pml4_phys`, user entry point, user stack bounds)
- Initial user bootstrap metadata (`user_stack_ptr`, `user_argc`, `user_argv`, `user_envp`, `user_auxv`, `user_fs_base`, `user_clear_tid`)
- Per-task ELF/program metadata (`phdr_*`, `base_addr`, dynamic-linker flags)
- Per-task program break tracking (`user_brk_start`, `user_brk`)
- Per-task file descriptor table metadata (`kind`, inode handle, file offset, open flags)
- Scheduling metadata (time slice, tick counters, sleep deadline)
- Saved x87/SSE register image (`fpu`, a 16-byte-aligned 512-byte `FXSAVE` area)

The boot task represents the current execution context and is created in `task::init()`.

**Kernel Threads**
`task::kthread_create()` allocates a kernel stack and builds an `InterruptFrame` at the top of the stack. When scheduled, the ISR return path restores this frame and begins execution at `kthread_entry_wrapper`, which calls the thread entry function and then `kthread_exit()`.

**User Task Bring-Up**
`kernel/src/user.rs` creates a minimal user task by:
- Creating a fresh address space with `vmm::create_address_space()`.
- Loading an embedded ELF64 image (`user/hello_dyn.elf`) into the new address space.
- If `PT_INTERP` is present, loading the embedded interpreter (`user/ld-peetos.so`) and entering user mode at the interpreter entry.
- Mapping a 32KB user stack at `USER_STACK_TOP = 0x7FFF_FF00_0000`.
- Writing a Linux-style initial stack (`argc`, `argv`, `envp`, `auxv`) before first ring-3 entry.
- Building an `InterruptFrame` that returns to ring 3 via `iretq`.

In the default build the initial user program is a small dynamic ELF that writes to stdout then exits via `int 0x80`. Feature-gated builds embed a different init ELF (for example the musl ext2 shell or a smoke-test driver); see `kernel/src/user.rs`. These init ELFs are generated by `make` and are not tracked in git.

**Process Lifecycle**
- `fork`, `vfork` and `clone` (with only `CLONE_VM`, `CLONE_VFORK` and an exit-signal in the flags) create a new process. Without `CLONE_VM` the child gets a full copy of the parent's user pages (`vmm::clone_user_space`).
- `execve` replaces the current process image.
- Exiting tasks become `Zombie`; `wait4` reaps them and frees their address space and task slot.
- Task state is visible from userspace via `/proc`.

**Scheduler**
`kernel/src/sched.rs` provides a simple round-robin scheduler:
- Run queue is a doubly-linked list of READY tasks.
- Time slices default to 5 ticks (50ms at 100Hz).
- The idle task runs when no other tasks are ready.

**Preemption and Yield**
- The PIT timer interrupt increments ticks and calls `sched::tick()` via a hook.
- When a time slice expires, `sched::tick()` sets a preemption flag.
- After the interrupt handler returns, the IDT post-handler hook calls `sched::isr_hook()` and performs a stack switch if needed.
- Voluntary yield and block/sleep paths build a synthetic interrupt frame in assembly (`sched_yield_asm`, `sched_block_asm`) to reuse the same return path.
- The scheduler updates `TSS.rsp0` on every task switch so user->kernel transitions have a valid kernel stack.

**FPU/SSE State**
- `crates/arch_x86_64/src/fpu.rs` wraps `FXSAVE`/`FXRSTOR` in `FxSaveArea`.
- The kernel is compiled with `-mmx,-sse,-sse2`, so kernel code never touches the x87/SSE register file. The live registers therefore always hold the *current user task's* state, and no lazy or trap-based switching is needed.
- `sched::schedule_from()` saves the outgoing task's registers into `Task::fpu` and restores the incoming task's image on every real switch (preemption, yield, block, sleep).
- New tasks start from the ABI-default image (x87 control word `0x037F`, MXCSR `0x1F80`, data registers zero).
- `fork`/`clone`/`vfork` snapshot the parent's live registers into the child.
- `execve` loads the default image after the new address space is committed.
- Signal delivery stores the interrupted registers in the kernel signal frame and enters the handler with the default image (as Linux does). `rt_sigreturn` restores the saved image after clearing MXCSR bits the CPU reports as reserved, so a corrupted frame cannot raise `#GP` in `FXRSTOR`.
- `fpu::init()` runs during boot (before `task::init()`) to detect the CPU's MXCSR mask and load the default state.
- Coverage: host unit tests for the image layout and MXCSR sanitising, plus the `musl-ext2-fpu-smoke` QEMU profile (`make run-fpu-smoke`, `tests/musl_ext2_fpu_smoke.sh`). That profile runs `user/fpu_context_smoke.c`, which checks XMM0-15, MXCSR and the x87 control word across preemption between four processes, across a signal handler that clobbers them, and across `execve`.

**Initialization Order**
1. `fpu::init()`
2. `task::init()`
3. `sched::init()`
4. Register PIT tick hook and IDT post-handler hook
5. `user::spawn_init()`

Limitations / Simplifications
- `execve` replaces the process image with caller-provided `argv`/`envp`; copy-on-write `fork` and `clone(CLONE_THREAD)` thread groups are described in `docs/process_model.md`.
- Dynamic-linking support is bootstrap-only (embedded `PT_INTERP` image, no reloc/symbol resolution).
- Per-task FD state includes baseline descriptor semantics (`dup*`, `fcntl`, and `FD_CLOEXEC` close-on-exec), but open-file-description sharing semantics are still simplified.
- No ASLR or stack guard pages; the stack is mapped at a fixed address.
- Per-task FS-base TLS state is tracked/restored (`arch_prctl` `ARCH_SET_FS`/`ARCH_GET_FS`), but GS-base handling and full TLS model compatibility are still incomplete.
- `user_clear_tid` zeroing performs a best-effort futex wake for one waiter at thread exit (`pthread_join`); robust-list semantics are not implemented.
- FPU/SSE switching is eager: every context switch pays one `FXSAVE` plus one `FXRSTOR`, even for kernel threads that never use the FPU. Lazy switching (`CR0.TS` + `#NM`) is not implemented.
- Only the legacy 512-byte `FXSAVE` image is managed. `CR4.OSXSAVE`/`XSAVE` is not enabled, so AVX/AVX-512 state cannot be used by userspace at all (CPUID reports OSXSAVE=0, so well-behaved code falls back to SSE).
- The signal-frame FPU image uses the PeetOS-private frame layout, not Linux's `ucontext_t`/`_fpstate`, so handlers cannot inspect or edit the interrupted FPU state through `ucontext`.
- `#XM`/`#MF` floating-point exceptions that userspace unmasks are not translated into `SIGFPE` with `FPE_*` codes.
- Zombie processes are reaped by `wait4`; exited non-leader threads are reaped automatically. Orphaned children are not reparented to init, so their zombies are only reaped if the original parent waits for them.
- Run queue operations are protected only by interrupt masking (single-core assumption).
